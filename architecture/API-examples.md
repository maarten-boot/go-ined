# API examples — go-ined

Generated by `scripts/gen-api-examples.sh` from a live `ined-server`. IDs, timestamps and `run_id` will differ on your system.
The steps run in order; each one depends on the ones before it.

```bash
ined-server -listen 127.0.0.1:8470 &
INED=http://127.0.0.1:8470
# With a token configured, add: -H "Authorization: Bearer $TOKEN"
```

```bash
curl -s $INED/api/v1/health
```

### Error: duplicate IP address

```bash
curl -s -X POST "$INED/api/v1/hosts" -d '{"ip":"192.168.1.10"}'
```

Response: `409`

```json
{
  "error": {
    "code": "conflict",
    "message": "IP address 192.168.1.10 already belongs to host 1"
  }
}
```

### Error: CIDR with host bits set

```bash
curl -s -X POST "$INED/api/v1/groups" -d '{"cidr":"10.0.0.5/24"}'
```

Response: `400`

```json
{
  "error": {
    "code": "invalid_argument",
    "message": "CIDR \"10.0.0.5/24\" has host bits set; use 10.0.0.0/24"
  }
}
```

## Services (Connect menu)

The server tries a TCP connection to ports 22, 3389, 5900-5909, 80 and 443 of each monitored host (when new, then every 6 h). `POST /hosts/{id}/check-services` checks one host now and answers the host with `services` (for example `["ssh","vnc:1","https"]`; `[]` when nothing answered) and `services_checked_at`; both are `null` before the first check. This run has `services.enabled = false`, so that the output does not depend on the ports open on the machine that ran it; the server then answers 503.

### Check the services of host 5 (checks turned off in this run)

```bash
curl -s -X POST "$INED/api/v1/hosts/5/check-services"
```

Response: `503`

```json
{
  "error": {
    "code": "unavailable",
    "message": "service checks are turned off on the server (services.enabled = false)"
  }
}
```

### The services of a host with inedctl (--check checks first)

```bash
inedctl host services 5
```

```text
not checked yet
```

Exit code: `0`

## Watched services

A host's `watch` list names the services to check every `services.watch_interval` (5 min by default): `ssh`, `rdp`, `vnc`, `vnc:1`…`vnc:9`, `http`, `https` or `tcp:N`. Each has a status (`up`, `down` after 2 failed checks in a row, `unknown` before the first check, while the host is not monitored and in this run, where checks are off), `last_change` and `last_ok`. A change of status sends `service.status`, for example `{"host_id":5,"display_name":"web","ip":"192.0.2.10","name":"https","port":443,"status":"down","last_change":"2026-11-16T14:07:10Z","services_down":1}` (`services_down` is the host's count of watched services down after the change); `/map` items of hosts have `services_down` too.
