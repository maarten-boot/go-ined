## 2. Code → Spec (bugs found in the code)

| # | Sev | Finding | Evidence | Proposed fix |
|---|-----|---------|----------|--------------|
| C1 | **M** | **A client that stops reading the event stream blocks shutdown.** The SSE handler blocks in `Write` once the socket buffers are full. The server has no write timeout (on purpose, for SSE), so the handler never returns. On SIGTERM, `http.Server.Shutdown` waits for it until `shutdownTimeout` (10 s), and then `run` returns an error, so the exit code is 1. This breaks SPEC-804. A frozen GUI or a suspended laptop is enough to trigger it, for example while 5,000 hosts clear `stale` after a restart | Probe: a client that never reads, with 16 MB of events published steadily: the handler was still blocked; `Shutdown` returned `context deadline exceeded` after its 2 s limit | Before every write, set a write deadline with `http.ResponseController.SetWriteDeadline` (proposed: 10 s); on a timeout, end the stream. Add the scenario to TC-802 (`api: TestEventsStalledClient`) |
| C2 | M | **Raw-socket mode probably doesn't scale to A1 (5,000 hosts).** Each round opens its own raw ICMP socket, and on Linux every raw ICMP socket receives a copy of every incoming ICMP packet. With about 250 rounds in flight (5,000 hosts, 60 s, up to 3 s per round), each reply is copied about 250 times. That costs CPU, and full receive buffers drop replies, which shows up as false loss or `down`. Unprivileged mode isn't affected, because the kernel delivers each reply to one socket | Reasoning from the code and Linux raw-socket semantics. **Not measured**: there is no `CAP_NET_RAW` here | In raw mode, share one socket per address family, with one reader goroutine that hands replies to the right round by (id, seq, token). Test raw mode in CI (C2 under §6) |
| C3 | L | **The echo requests in a round go out back to back.** As soon as a reply arrives, the next request is sent, so all 3 go out within about 1 ms. Some routers and firewalls rate-limit ICMP, which then shows up as loss | `internal/monitor/icmp.go` | Wait at least 200 ms between requests in a round. Add this to SPEC-302 |
| C4 | L | **`last_seen` is the end of the round, not the time of the last reply** (SPEC-303). It can be up to `count × timeout` (3 s) late | `monitor.go`: `at: m.cfg.Now()` after `Ping` returns | `Result` gets `LastReply time.Time`, and the monitor uses it for `last_seen` |
| C5 | L | **ICMP mode detection only tests IPv4.** On a machine without IPv6, or where only IPv4 is allowed, every IPv6 host fails every round and goes `down`, while `/health` says all is well | `NewICMPProber` opens only `udp4` and `ip4:icmp` | Detect the mode per family. When IPv6 isn't available, don't ping IPv6 hosts (they stay `unknown`) and report it in `/health` as `icmp6_error`. Add this to SPEC-304 |
| C6 | L | **Turning monitoring back on shows the old status as current.** The host isn't `stale`, but its status is whatever it was when monitoring was turned off, possibly days ago | `UpdateHost`: `Monitored` false → true keeps `Stale = false` | Monitoring on → `stale = true` until the first round. Add this to SPEC-603 and TC-603 |
| C7 | L | `api.Keepalive` is a package variable that a test changes | `internal/api/sse.go` | Make it an `Options.Keepalive` field (0 = 30 s) |

## 9. Resolution (2026-11-10)

The user approved **all** fixes, plus C8 (found afterwards, from the new global temp-files rule): `scripts/gen-api-examples.sh` created its temporary folder loose in `/tmp`. The code is on branch `fix/crosscheck-03`; the docs are in Spec v0.10, Plan v0.10 and Tests.md.

- **C1:** before every frame, the SSE handler sets a write deadline (`Options.WriteTimeout`, default 10 s). Added SPEC-502 text and **TC-509** (`api: TestEventsStalledClient`). The test was confirmed to fail without the fix.
- **C2:** in raw mode, all rounds of a family share one socket. A reader goroutine matches each reply by (echo id, seq), peer and token. Ids are unique among open rounds. A failed socket fails the rounds and is reopened on next use. Added **TC-314**, which runs 250 concurrent rounds with noise on a fake raw socket. A real raw socket is still untested (§6, item 1).
- **C3:** a round's requests are at least 200 ms apart (SPEC-302, **TC-312**).
- **C4:** `Result.LastReply`, and `Observation.SeenAt` → `last_seen` (SPEC-303, **TC-315**).
- **C5:** the mode is chosen per family, and `monitor.Status` reports `IPv4Error` and `IPv6Error`. Hosts of an unavailable family are skipped and their status stays as it is. `/health` adds `icmp6_error`, and `status` is `degraded` only when no family works (SPEC-304, SPEC-501, **TC-313**).
- **C6:** monitoring off → on sets `stale` (SPEC-603, TC-603).
- **C7:** `Options.Keepalive`. **C8:** `/tmp/go-ined/gen-examples.XXXXXX`, removed on exit.
- **S1, S2:** in SPEC-501 and SPEC-302. **P1:** 7 tests mapped in Tests.md. **P2:** the handover is marked superseded. **P3:** local branches deleted; the remote delete is for the user.

After the fixes: `make all` passes. `make examples` gives the same output apart from ids and timestamps. A smoke test with the real binary showed 127.0.0.1 up, `/health` with `icmp_mode: unprivileged`, and a clean SIGTERM (exit 0).
