## 2. Code → Spec (bugs found in the code)

| # | Sev | Finding | Proposed fix |
|---|-----|---------|--------------|
| C1 | M | **Expanding a group that is already expanded moves its contents.** `setCollapsed(id, false)` computes the frame the group "would have if expanded" and moves the contents so that it starts at the icon's stored corner. That is right for a collapsed group. For an expanded group, the stored position is the old icon's, not the frame's, so the contents jump. Probe 1: "Expand 2 groups", with `b` collapsed and `a` already expanded, moved `a`'s host from 400,400 to 120,130. That is a change of position for everyone, which nobody asked for. The key **e** has done the same since 0.2.0 (SPEC-724). The menu only makes it easier to hit, because "Expand N groups" is enabled when any one of them is collapsed. | `setCollapsed` leaves a group alone when it is already in the requested state: no move and no PATCH (this also saves a reload for "Collapse" on a collapsed group). Add a test (TC-726, 727): a mixed selection, then Expand from the menu and with **e**, and the expanded group's members keep their positions. SPEC-724: "groups already expanded (collapsed) are left as they are". |

Checked and fine:
- **Probe 2:** the "Host labels" row is right in both cases ("IP address"; "As the parent group (Name and IP address)"). The details refill after each map reload (`redraw` → `refreshParent`).
