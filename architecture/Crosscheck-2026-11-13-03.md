## 1. Code → Spec (bugs found in the code)

| # | Sev | Finding | Proposed fix |
|---|-----|---------|--------------|
| C1 | M | **Expanding a group inside a focus doesn't keep its corner** when a group above it is collapsed on the shared map. `setCollapsed` asks `FrameIfExpanded` where the frame would be, and that lays out the *whole* view, where the group is hidden under its collapsed parent. So it reports "not visible" and the contents aren't moved first. Probe 1: the frame opened at 658,648, by the host, instead of at the icon's corner 180,178 (SPEC-703). The move is saved, so it changes positions for everyone. It happens with **e**, double-click and the menu; collapsing is fine, because it uses the frame on screen. | `FrameIfExpanded` lays out with the group's ancestors treated as expanded too (flags restored), as `ReflowCell` already does, since a frame's size depends only on its own subtree. Test (TC-725): expand inside a focus whose group is collapsed, and the frame starts at the icon's corner. |
| C2 | M | **Typing a view's name in the "Show" list jumps there mid-word.** Picking from the list and typing both arrive as a text change. A text equal to an entry counts as a pick, and view names have no indentation. Probe 2: after "Lab" the tab switched to Lab and the cursor left the list, so in real typing " east" goes to the map's key handler; there **e** expands the selected groups (and **g**, **j**, **c** and **o** act too). Group names are safe only because of their indentation. | Treat a change that adds one character to the previous text as typing: it only filters. Picking from the list (the text replaced as a whole) and Enter still show the entry. Test (TC-733): typing "Lab east" one letter at a time stays in the list and doesn't switch tab; picking "Lab" does. |

Checked and fine:
- **The key j:** one group acts at once, several ask (primary group first), hosts in a selected group stay, and the hint shows without a group or host. Custom views use placements (`setParentAt`).
- **Focus paths:** collapsing inside a focus uses the frame on screen (correct); new items, **g**, Reflow ("Reflow group X…", using the crosscheck-16 fix for a collapsed focus group) and dragging behave as SPEC-726 says. Find host only expands collapsed groups below the focus. A deleted focus group moves the focus up. The trail's borders don't pile up.
- **The trail of an unloaded view** fills in once its map has loaded (a few milliseconds).
