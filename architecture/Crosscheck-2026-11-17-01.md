## 1. Code → Spec (bugs found in the code)

| # | Sev | Finding | Proposed fix |
|---|-----|---------|--------------|
| C1 | M | **`ined-alert`: a state file that is valid JSON of the wrong shape stops the program** instead of being moved to `.bad` (SPEC-956). `load_state` catches only unreadable JSON. `Engine.__init__` then raises on, for example, `{"open": []}`, `{"server": null}` or `{"services": {"x": {}}}` (all three checked). systemd restarts it every 10 s, forever. A future `version` is accepted silently. | Build the engine's state inside the same guard: on any error, move the file to `.bad`, log `state_unreadable` and start empty. Refuse a `version` above 2 the same way. Test (TC-950). |
| C2 | M | **`ined-alert`: a recovery is mailed without the server's word when the server can't be asked.** For an UP event (host or service), a failed read (`OSError`) falls back to the event itself (`h2 = h`). So a stale "up" event during a short server outage closes the alert and mails "UP". SPEC-952 says the up alert is "also checked with the server", and the down path waits instead. | On a failed read keep the alert open and confirm at the next tick, as the down path does: a pending-recovery list checked in `tick`. Test (TC-952, TC-957). |
| C3 | M | **`services.enabled = false` leaves watched services in their old state**, not `unknown` as SPEC-310 says. Nothing resets them when the Watcher isn't started. A service that was `down` stays `down` with `services_down` 1, so the GUI marker and `ined-alert` keep a problem that can never end. The start log even says "watched services stay unknown". | At start with services off, set every watched service that isn't `unknown` to `unknown` (as `resetWatch` does, with `service.status`). Test (TC-318). |
| C4 | M | **Import with "update existing" leaves matched groups where they are, without saying so below the top.** A matched group other than the top one keeps its parent and position. The file's items below it go into it, and an unmatched group above it in the file stays empty. Only the top group gets the "updated where it is" warning. The design (N8) and SPEC-125 also say "positions … are set" for matched items, which is true for hosts only. | Warn for every matched group whose server parent differs from its parent in the file. Reword SPEC-125 and N8: matched groups keep their place and position (moving a frame without its other contents would break it); hosts get the file's position. Test (TC-132). |
| C5 | M | **GUI: two "Import here…" items with different targets.** With a focus group set, a group's menu has "Import here…" into that group and, from the focus's "new items", "Import here…" into the focus group at the click. They look the same. | Call the group's own item "Import into this group…"; "Import here…" stays for the spot that was clicked. Test (TC-751). |
| C6 | M | **`ined-alert`: an alert counts as sent once it is queued.** If the relay stays down past the retries (10 s, 1 min, 5 min), the mail is dropped (logged `mail_dropped`), but the alert stays open in the state file. Its recovery mail later goes to people who never got the DOWN. SPEC-954 says only "then dropped". | Say so in SPEC-954 and the README: a dropped DOWN mail is logged as an error and its recovery is still sent. Re-queueing dropped mail is left for later, since the relay is local (A7). |

**Smaller findings (L):**

- **Export and import:**
  - **L1:** two plain sibling groups with the same name in one file are imported as two groups. With "update existing" both match the same group: it is counted twice and gets two events. Fix: refuse such a file ("group … twice").
  - **L2:** group names match exactly, so "Printers" ≠ "printers"; custom-view paths with two sibling groups of one name go to the lowest id. Fix: say both in SPEC-125.
  - **L3:** `inedctl group export -o` keeps the mode of an existing file (0644 stays 0644), while SPEC-905 says 0600. Fix: set 0600 after writing.
- **Watched services:**
  - **L4:** a watch list given again keeps a service's status by name only, so `ssh` → `tcp:22` (same port) starts `unknown`. Fix: also match by port.
  - **L5:** `inedctl host watch 5 ""` clears the list (an empty variable in a script would do it); `--add` of a watched service is a 400. Fix: an empty LIST is a usage error; `--add` of a watched service does nothing.
  - **L6:** in the GUI's "Other TCP ports", "tcp: 5432" reports `"" is not a port number`. Fix: allow blanks after `tcp:`.
  - **L7:** a narrow race: a check in flight for a service removed from the list can leave a failure count that a re-added service inherits (down after 1 failure). Fix: count only keys still watched when the result arrives.
- **`ined-alert`:**
  - **L8:** a host without `watch` (a server downgraded below v0.50) keeps its open service alerts until it is deleted. Fix: close them in a fresh snapshot.
  - **L9:** a wrong token is reported as "the server doesn't say what the token may do (an older server?)", because `/health` answers without a token. Fix: say "token not accepted" when the authenticated fields are missing.
  - **L10:** a route with `to = []` is accepted without a word. Fix: a warning, like a route that matches nothing.
  - **L11:** mail is sent from the main loop, so an unreachable relay delays event handling by up to 10 s per attempt. Unverified; events are queued meanwhile. Fix: none now; noted.

Checked and fine:

- **Read token** (SPEC-808): changes are refused with 403, tokens are compared in constant time, and `access` appears in authenticated `/health` only.
- **`ined-alert` (SPEC-950–957):**
  - reconnecting and resuming the event stream;
  - routes and recipients, frozen when the alert is sent;
  - held service alerts, logged once, and mailed `down_after` after the host is back;
  - an open service alert while the host is down: no repeats;
  - state file versions 1 and 2, written atomically with mode 0600;
  - mail subjects and bodies;
  - config checks;
  - `--check` and the exit codes.
- **Services found** (SPEC-309): the ports, when a host is due, the 10 at once, an IP change, the 409, 404 and 503 answers.
- **Watched services** (SPEC-310, 311, 512, 904, 732):
  - stale results are dropped (deleted or unmonitored host, new IP, unwatched service) under the lock;
  - a host back up is checked at once;
  - migration 7, and its rows removed with the host (also in a group delete);
  - the events carry the final `services_down`, and the GUI's model and details follow them;
  - the GUI's dialog for several hosts behaves as described.
- **Export and import** (SPEC-125, 513, 733, 905):
  - a failed save leaves the model and the next ids unchanged, and a dry run changes nothing;
  - the item limit is exact (10,000 accepted, 10,001 refused); depth 32 is accepted, 33 refused;
  - `group_id` for a matched top group, and positions relative to it;
  - no cycles when the target is inside a matched group;
  - an empty custom-view path means the view's top level;
  - the 409 body, the read token, and the 32 MiB limit on `/import` only;
  - `inedctl` exit codes, and the GUI's import position.
- **GUI** (SPEC-713, 717, 727–729, 708, 721, 724):
  - fit-on-resize: the stored size, a new size fits again, and a hidden tab fits when next shown;
  - the version check (releases only; X.Y.Z compared);
  - "Show in view" copies;
  - the details' selectable values and the note below them.
