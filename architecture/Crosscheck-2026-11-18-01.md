## 1. Code → Spec

### File dialogs (`feature/file-dialogs`)

| # | Sev | Finding | Proposed fix |
|---|-----|---------|--------------|
| C1 | H | **A file name with `+`, `%`, `#` or `?` gives the wrong file.** The portal package already decodes the URI it gets (`url.QueryUnescape`), and `firstPath` decodes it again (`url.Parse`). Repeated by Claude with the same two steps: `a+b.json` → `/tmp/a b.json`; `a#b.json` → `/tmp/a`; `100%.json` → a parse error. Export then writes to another file than the one chosen, without the overwrite question for it (here `/tmp/a`); import reads another file. Spaces and non-ASCII are fine. | Decode once. Turn the portal's answer into a path without a second decode, and keep `+` (the package's `QueryUnescape` turns it into a space): call the portal's D-Bus method ourselves through the package's lower layer, or undo the package's damage where it can't be told apart (prefer the first). Tests for `+`, `%`, `#`, `?`, a space and non-ASCII. |
| C2 | H | **A portal answer "ended" (status 2) crashes the GUI.** The package checks only "cancelled"; for "ended" (a backend that dies, a window closed some other way) it does `results["uris"].Value().([]string)` on a missing value, which panics in our goroutine without a `recover`: the whole program stops. Read in the package's source (`filechooser.go:23`, `request.go:43`), not run. | Recover in the goroutine that calls the desktop's dialog and treat a panic as an error ("the file dialog failed"); with C1's own call, check the status and the value. |
| C3 | H | **Export empties the old file when the export then fails.** The file is created (truncated) as soon as the dialog returns; the server is asked afterwards (`exportTo`). If the server is down or refuses, the user's earlier export is left empty. Also in Fyne's dialog, and so since 0.6.0. | Ask the server first and write only when the data is there: write to a temporary file in the same folder and rename it over the chosen one. |
| C4 | M | **Any error of the desktop's dialog opens Fyne's dialog too**, also an error after the user chose a file (C1's parse error, C2). The user gets a second dialog for the same action. | Fall back only when the desktop's dialog can't be opened (no D-Bus, no portal, `zenity` missing); report other errors in the status bar. |
| C5 | M | **Two file dialogs at once can mix up their answers, and a hanging portal hangs for ever.** The package waits for any `Response` signal of the portal, not the one for its own request, never stops listening, and has no timeout. A second Export or Import while a dialog is open starts a second dialog; either can take the other's answer. Read in the source, not run. | Allow one file dialog at a time (the menu items say so in the status bar while one is open: "a file dialog is open"). With C1's own call, wait only for the own request's path. |
| C6 | M | **`Chmod(0600)` after `os.Create` changes the mode of an existing file and leaks the file when it fails.** On an existing file the user's own mode is replaced; when `Chmod` fails the open file isn't closed. | Use `os.OpenFile(path, O_WRONLY\|O_CREATE\|O_TRUNC, 0o600)` (with C3: the temporary file), so a new file is 0600; say in SPEC-733 that an existing file keeps its mode, as `inedctl` does not (see L3), or make both the same (recommended: both 0600, as SPEC-905). |

### Positions (`feature/round-positions`)

| # | Sev | Finding | Proposed fix |
|---|-----|---------|--------------|
| C9 | M | **Reflow saves groups unrounded.** `Arrange` rounds hosts and placements but not member groups: a cell width of 123.456 gives a group `X = 163.45600000000002` (the reviewer's probe). The GUI's reflow sends measured cell sizes, so it happens in normal use. Model and store agree; only the rule of SPEC-106 is broken. | Round the cell positions (`nx`, `ny`) once, before the comparison, and the shift given to the subtree. Test in TC-135. |
| C10 | M | **A move can reach infinity.** A host at x = 1.7e308 in a group moved by 1.7e308 gets x = +Inf: no error, and the host can't be encoded as JSON any more, so every answer that includes it fails (repeated by Claude: `json: unsupported value: +Inf`). Older than the rounding, which keeps it. Needs absurd input from someone with the full token. | Refuse positions beyond ±1e9 (`fixPos`), and a move whose result would be beyond that, with "position out of range". Test. |

**Smaller findings (L):**

- **File dialogs and hover:**
  - **L1:** a file over 64 MiB is cut to 64 MiB and then reported as "not a JSON file". Fix: say "larger than 64 MiB".
  - **L2:** files saved through Fyne's fallback dialog keep Fyne's mode (0644). Settled by C6.
  - **L3:** the hover box doesn't follow `host.status`/`service.status`, and stays open over a redraw, a deleted host or a tab switch by key until the pointer moves. Fix: close it when the map's nodes change or the tab changes.
  - **L4:** the hover timers are invalidated but not stopped (a few can wait 0.5 s for nothing). Fix: keep the timer and stop it.
  - **L11:** `TestFileDialogs` failed once under `-race` in CI (`feature/marker-help`, run 44293931801): the test replaces `nativeSave` while the goroutine of the previous Export still reads it (`filedialog.go:41`). Only the test is affected, but it makes CI flaky. Fix: `saveFile` and `openFile` take the function on the UI goroutine before starting theirs.
- **`ined-alert` and `inedctl`:**
  - **L5:** `_renamed` drops a waiting service of the new name but leaves it in `svc_held`, so its "held" line may not be logged again. Fix: `_drop_svc`.
  - **L6:** `inedctl host watch 5 --add ssh` with `tcp:22` watched still gets the server's "same port" 400. Fix: skip by port too.
  - **L7:** `group export -o /dev/stdout` as a normal user writes the data, then fails on `chmod` with a usage error. Fix: change the mode of regular files only.
  - **L8:** the watcher fix of L7 (2026-11-17-01) narrows the window but doesn't close it: a service removed and added again within one round, while a check is in flight, still counts. Fix: a generation per service key, compared when the result arrives. The Spec's wording ("counts for nothing, also when added again") goes too far until then.
- **Positions:**
  - **L9:** after a reparent, `group.moved` carries the rounded offset, which differs from the group's own move by less than 0.05 when its old position was unrounded (older data only). The GUI reloads anyway. No fix; noted.
  - **L10:** saving any change to an item with an old unrounded position rounds it and sends an event; as designed (P2). Noted.
