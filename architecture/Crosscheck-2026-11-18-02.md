## 1. Code → Spec

### Server (`internal/discovery`, `internal/inventory`)

| # | Sev | Finding | Proposed fix |
|---|-----|---------|--------------|
| C1 | M | **One group that can't be scanned stops the whole schedule.** `scheduleOnce` returns after any error but a conflict. The group that failed is never scanned, so it stays due longest and comes first again at every check; no other group is ever tried. Example: a /16 with a rescan, then `discovery.max_prefix` lowered to 24 and the server restarted ("range … is too large"). The same would happen with any lasting error for one group. Repeated by Claude: with `max_prefix` 28, a /24 and a /30 both with rescan 1h, no job ran and the /30 was never scanned. | On an error for one group, set its `later` to now + Retry (5 min), log it, and try the next group. A group whose range is larger than `max_prefix` is skipped with one warning per group. |
| C2 | M | **A group with a rescan can't be edited at all once `discovery.max_prefix` is lowered.** `UpdateGroup` checks the rescan on every PATCH, so a rename, move, note or colour change is refused with "range … is too large to rescan". The way out, `rescan: off` in the same PATCH, isn't obvious. Repeated by Claude (a /16 with rescan 1h, limit set to 24, then a rename: 400). | Check the rescan only when the PATCH sets `rescan` or `cidr`. SPEC-206 then says that a rescan made invalid by a lower `max_prefix` stays, isn't run (C1), and is shown in the log. |
| L1 | L | The wait after a user's cancel (one interval) or a failure (5 min) outlives a change of the group: turning rescan off and on, a new interval or a new CIDR doesn't clear it. SPEC-206 says "turning it on makes it due at once"; after a cancelled round, it can wait up to the old interval. | Keep the setting (interval and CIDR) with the wait, and ignore the wait when the setting has changed. |
| L2 | L | A `rescan_last` in the future (the clock set back, or a bad value) holds the group until then. | Treat a `rescan_last` after now as due. |
| L3 | L | A job that ends `done` with every probe failing (for example "network is unreachable") counts as a scan, so the group waits a whole interval. | Count such a job as failed for the schedule (retry after 5 min), and say so in SPEC-207. |
