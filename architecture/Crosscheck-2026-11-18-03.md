- **The user's question during the fixes:** "the cpu% > 100 should be investigated how that works for multi cpu servers".
  - `hrProcessorLoad` (HOST-RESOURCES-MIB, RFC 2790) is defined per processor row as `Integer32 (0..100)`: the percentage of the last minute that processor wasn't idle. Agents give one row per logical CPU (net-snmp on Linux one per CPU in `/proc/stat`, Windows one per logical processor).
  - So no row is above 100, and the average over the rows, which is what the server shows, is the whole machine's load: 0–100 however many CPUs there are. The 125 % of C4 came from a broken (fake) agent's −5 and 255.
  - What the average hides: one CPU at 100 % on a 16-CPU server shows as about 6 %. A Unix load average (UCD-SNMP-MIB `laLoad`) can be above the number of CPUs, but it isn't read.
  - Possible addition, waiting for the user: also show the number of CPUs and the busiest one ("CPU 6 % (16 CPUs, busiest 100 %)"), and offer it as a metric for part 2's thresholds.
