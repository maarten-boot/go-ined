| C1 | M | **An agent that answers the system group but never its values is searched at every tick, once the waits are used up.** After the 1, 5 and 30 min waits, `away()` returns false without setting the next time, and `find` ignores that on the "found" path; with the next time in the past, `work` starts a search every 10 s, each with every request timing out. Repeated by Claude: with the clock frozen after the waits, 60 searches in 300 ms. Section 7 of 2026-11-18-03 held only for an agent that is silent altogether. | When the waits are used up: for an agent that still answers its system group, keep it and wait `rescan` (24 h) before the next search; say so in SPEC-312. | C2 | M | **Hosts without an agent are all tried again after every restart.** The shortcut "same result: not written" (2026-11-18-03 C2) also covers "no answer", so the stored time stays at the first check; after a restart every such host looks overdue and is tried at once with every community and version. ### `ined-alert` (thresholds)

| # | Sev | Finding | Proposed fix |
|---|-----|---------|--------------|
| C3 | M | **Old values keep an alert open and repeating.** When a host or its agent stops answering, the server keeps the last values until the agent is given up (C1, hours), and `ined-alert` doesn't look at their time: STILL HIGH keeps going out with a stale value, and a new HIGH can come from one. Repeated by Claude: with the host down, the tick sends DOWN and STILL HIGH. | Treat values older than 3 × the read interval (15 min; `values.at`) as no values, and hold HIGH and STILL HIGH while the host is down, as service alerts are held (S8). |
| C4 | M | **An OK or STILL HIGH mail shows the line of when the alert opened.** After the line is changed in `alert.toml` (90 → 95) and a restart, an OK at 92 % says "at or below 90 %". Repeated by Claude. | Update the open alert's line and label from the current rule. |
| C5 | M | **Two memory entries read the same in the mail.** Agents that report "Physical memory" and "Virtual memory" with kind memory get two alerts, both "memory 95 %". Repeated by Claude. | Name the entry when a host has more than one: "memory (Virtual memory) 95 %". |
| L6 | L | Windows disk names make long subjects ("disk C:\ Label:  Serial Number 1234 92 %"). | Use the part before " Label:" ("disk C:\"). |
| L7 | L | A rule removed or changed ends its alerts with the log reason "no values". | Log "no rule" then. |
| L8 | L | The start's `loaded` log line doesn't count open threshold alerts, and the start summary doesn't list them. | Count them in the log line; list them in the summary as "These values are high:". |
