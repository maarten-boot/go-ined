## 1. Code → Spec

| # | Sev | Finding | Proposed fix |
|---|-----|---------|--------------|
| C1 | H | **A quick check leaves "Cancel SNMP check" in the status bar for good.** The answer to `POST /snmp/checks` always says "running", and the GUI registers the job only when that answer arrives. A `snmp.check.finished` event that comes first is ignored, so the job stays registered: "SNMP check: 0 of 1 hosts checked" and the button stay. Cancel then sends no event, so nothing clears it. The same happens when a job ends during a reconnect. The reviewer's probe: 10 of 40 runs stuck; Claude found the cause in the code. | After registering the job (and after a cancel), read it once with `GET /snmp/checks/{id}` and show that; keep events for unknown jobs for a few seconds and apply them when the job is registered; after a resync, read the GUI's running jobs again. |
| C2 | H | **`inedctl --json snmp check … --wait` exits 1 at once.** In `--json` mode the answer isn't decoded into the job, so the wait loop sees no state, prints an empty job and returns "the job did not finish" while the job runs on. Repeated by Claude (exit 1, the job still running). | Decode the answer in `--json` mode too; print the start answer and the final job as one JSON line each. A test. |
| C3 | M | **A changed community list is lost for hosts past `snmp.concurrency`.** `work()` records the new list before `Run` knows a slot is free. When none is, the job is dropped, and at the next tick the list counts as seen: those hosts keep the old agent until their next read or rescan (up to 24 h). The reviewer's probe: with concurrency 1, only one of three hosts was asked with the new list; Claude found the order in the code. The same goes for a host moved below another group. | Record the list only when the job starts (in the job, after the slot is taken). A test with concurrency 1. |
| C4 | M | **A group's right-click is slow with many hosts.** Counting the hosts for "Check SNMP now (N hosts)" rebuilds the group's subtree for every host, under the GUI's lock. Repeated by Claude: 800 hosts take 54 ms; the reviewer measured 5,000 hosts at 3.4 s, with the map and events blocked meanwhile. | Build the subtree once and count the hosts in it. |
| L1 | L | After `Close`, a `POST /snmp/checks` that still arrives starts a job nothing stops (a short window at shutdown). | A "closed" flag; such a start answers 503. |
| L2 | L | Counts of a cancelled job: hosts never started aren't counted, hosts stopped by the cancel count as skipped, and progress is sent only after a host answered or not. A host changed during its check counts as found or no answer. | Count unstarted hosts as skipped at the end; send progress after every host; count a changed host as skipped. |
| L3 | L | A group's new list sends `group.updated` only; its hosts' `snmp_communities_from` changes without `host.updated`, so the GUI's host details show the old origin until reloaded. | Send `host.updated` for the hosts below whose origin changed. |
| L4 | L | The job's `group_id` shares the caller's pointer. | Copy the value. |
| L5 | L | A host that leaves `snmp.networks`, or whose list is removed so it may no longer be asked, keeps its old agent and values. | Note only: the next host change or check clears them; documenting it in SPEC-315. |
| L6 | L | `POST /snmp/checks` with SNMP off and a bad body answers 400, not 503. | Check "off" first. |
| L7 | L | `inedctl … snmp-communities a, b` keeps the space (" b"); stdin lines keep trailing spaces. | Trim each entry. |
| L8 | L | `group show` of a custom-view group says "Communities: none set here", though none can be set there. | Say "– (custom view)". |
| L9 | L | The dialog closes before the server answers, so typed strings are lost on an error; "Add" at 10 rows gives no hint; padded strings are kept as typed. | Close after a successful save, keep it open with the error otherwise; say "at most 10"; trim. |
| L10 | L | Mixed selections: on a group in a selection, "Check SNMP now" counts only that group; on a host in a selection with groups, only the hosts. | Count every selected host and every host below the selected groups, and check them in one job. |
| L11 | L | The usage text puts `snmp check` and `snmp list` between the `discover` lines; the cancel button cancels all of this GUI's checks but says "check". | Move the lines; "Cancel SNMP checks" when more than one runs. |
| L12 | L | The SNMP menu items show also when SNMP is off on the server; the click then gives the server's reason. | Note only (the GUI doesn't know the server's setting). |
