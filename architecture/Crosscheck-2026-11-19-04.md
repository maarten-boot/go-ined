| C1 | M | **An event while the details pane loads a host is lost.** Since the 2026-11-19-03 C1 guard, `reload()` does nothing while `show()` loads, i.e. on every new selection. A `placement.updated`, `view.updated` or group event that comes after the server answered `show()`'s GET, but before the answer is applied, is dropped: the "Views" and "SNMP communities" rows stay old until the next event. Reviewer 2's probe: the GET's answer held back, the host placed in a view meanwhile: the pane said "Views: Networks", the server `[1 2]`. The window is one GET long. | When the key is a host whose `show()` is still loading, remember that an event came; when the answer is applied, read the host once more. The guard against a host under a group's title stays. |
| C2 | M | **A 401 stops following an SNMP check.** The 2026-11-19-03 rule ends following on any 4xx; a wrong or changed token gives 401: Cancel goes, the status says "no longer known to the server", and the job runs on. Reproduced by reviewer 2 (a client with a wrong token). | End following only on 404 and 503 `unavailable`; on other answers keep it and say "not read". Spec v0.68 and TC-759 change with it. |
| L1 | L | Every `view.updated` reads the shown host again, also for renames and reorders of other views; "Move view left" after a deleted view renumbers several views: 3 GETs in the probe. | Read it again only when the host is placed in that view, or coalesce the reads. |
| L2 | L | "from view 7" when the GUI's model doesn't know the view yet (just created or deleted). | Keep; it is short-lived. |
| L3 | L | For a view without a list the dialog says "none set here (inherited)", which says little for a view. | For a view: "none set here; its hosts use their group's or the server's list". |

| L6 | L | A host's `snmp_communities_from` can change through a view (place, unplace, reorder, a view's list, a view deleted) without a `host.updated`; a client that reads only host JSON from events sees the old origin.
