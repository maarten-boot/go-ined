## 4. Design in brief (details: Spec v0.7, Plan decisions D1–D11)

- **Programs:** `ined-server` (done), plus `ined-gui` (Fyne) and `inedctl`, which are both planned.
  - The server serves REST under `/api/v1`. SSE is planned.
  - Storage is SQLite through `modernc.org/sqlite` v1.62.0 (pure Go). Config is TOML through `BurntSushi/toml` v1.6.0.
- **Tree model:**
  - Hosts and groups form a tree.
  - A group with a `cidr` is a **network group**. Its CIDR must be canonical and unique, and nested network groups must fit inside their parent's range.
  - A host added without a parent goes into the most specific network group containing its IP.
  - `outside_cidr` is informational only.
  - Each item has one plain-text note (at most 64 KiB).
  - Groups have a `collapsed` flag. It is stored on the server, shared by all clients, and true for new groups.
  - Positions are stored on the server, on one shared map.
  - A group's status is the worst status of the monitored hosts below it: down > unknown > up.
- **Ids:** never reused. They come from the `meta` table, added in migration 2.
- **Server:**
  - Exclusive database lock (SPEC-604); repairs the tree at load (SPEC-605).
  - Listens on loopback by default. Any other address requires a token. `/health` without a token returns only status and version.
  - Optional TLS.
- **Code layout:**
  - `internal/inventory`: the model, the rules, and a `Service` that holds the whole inventory in memory behind a mutex and writes every change through to the `Repository`.
  - `internal/store`: SQLite.
  - `internal/api`: HTTP.
  - `internal/config`: config loading.
  - `pkg/apitypes`: the JSON types. PATCH bodies use `Opt[T]`: an absent field is not changed, and `null` sets it to the zero value.
  - `cmd/ined-server`.

## 5. Next step: M2 (monitoring and events)

From Plan.md. Spec: SPEC-301..306, 105, 502, 503, 603, 804; tests: TC-301..307, 112, 502, 506, 602, 703, 802.

1. **`internal/events`:**
   - An event bus with a replay buffer (`events.buffer`).
   - Event ids are `<run>-<seq>`. The run id already exists in `cmd/ined-server` (`newRunID`) and is reported by `/health`.
   - A client reconnecting with an id that has left the buffer, or that comes from another run, gets `resync`.
2. **`GET /api/v1/events`** (SSE):
   - The handler must close its streams on shutdown (SPEC-804, TC-802 partial).
   - The server deliberately has no `WriteTimeout`, so streams can stay open.
3. **Hook mutations into events:**
   - `inventory.Service` has no notifier yet. Add one, emitting `host.*` and `group.*` events.
   - Emit `group.status` whenever a group's computed status changes, for any cause (SPEC-305): compare `Aggregate()` before and after each change.
4. **`internal/monitor`:**
   - An ICMP prober behind an interface, so tests can use a fake.
   - Use unprivileged ICMP first and fall back to raw sockets; report the mode in `/health` (currently `"not started"`).
   - Proposed library: `prometheus-community/pro-bing`. Check its latest version, and the licence fits MIT.
   - The scheduler spreads ping start times across the interval. Status rules come from SPEC-302. Results go through the Service and are persisted (SPEC-603). The `stale` flag clears after the first ping round.
